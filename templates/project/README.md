# 项目名称

用一句话说明为谁解决什么问题。此文件是写作模板，不代表已完成项目。

## 背景与目标

写清真实业务场景、现有痛点、目标用户，以及本次不做的事情。

## 方案与架构

说明系统入口、主要模块、数据流与外部依赖。区分完整系统和本仓库公开的部分。

## 关键实现

挑选两到三个能够通过代码验证的设计点，链接到具体文件，解释问题、选择和代价。

## 我的贡献

根据实际情况填写需求分析、架构、代码、测试、联调或部署职责，区分个人工作、协作与 AI 辅助实现，不夸大独立完成范围。

## 运行与验证

提供最低依赖、运行命令、测试命令、期望输出和外部服务限制。测试数据应为合成或经过授权的脱敏数据。

## 工程案例

记录一个实际问题：现象、证据、根因、修复、回归，以及尚未验收的部分。

## 结果与限制

只填写有依据的数据，区分测试通过与业务效果，不虚构准确率、性能或成本收益。明确当前缺失的能力。

## 公开检查

确认已移除凭证、个人信息、内部资料、生产地址和未经授权的媒体；更新根目录项目索引并运行仓库检查。
