# 工程文件翻译工作台

[直接体验 · 无需登录](https://niko-97xq.github.io/project-portfolio/engineering-translation/)

把英语、马来语混排的工程文件译成中文时，译文正确只是第一步。如果把 600 mm 写成 60 mm，或一段译文没有写回图纸，导出的文件仍不能交付。本项目围绕这两个问题组织翻译和检查。

**一分钟体验：** 打开样张，对照左右两栏，点击「模拟漏译与数字错误」。检查结果会从 3/3 变为 1/3。改正数字并补回空白项，即可看到核对结果实时更新。示例译文已预置，浏览器执行的是从正式项目提取的规则；不上传文件、不访问公司系统。

| 环节 | 正式系统的做法 | 可审阅材料 |
| --- | --- | --- |
| 识别与翻译 | PDF 优先读文字和位置，扫描图或轮廓字用图像辅助；区分技术文字、签名与标识。选定模型后用于翻译、自查与修订 | [逐页提示词](page-prompts.ts) |
| 写入与检查 | 原位写回，核对数字、公差、单位及渲染记录。不能安全写入时保留原文并报告位置 | [数值规则](../../docs/engineering-translation/checks.mjs) · [写入与整页覆盖检查](../../docs/engineering-translation/page-completeness.mjs) |
| 恢复与交付 | SQLite 队列将逐页任务交给独立进程；保存每页检查点，恢复时跳过已完成页；网页可预览已生成页面 | [离线交互演示源码](../../docs/engineering-translation/demo.mjs) |

**设计取舍。** 已识别条目全部写入，并不等于图上没有漏译。因此正式流程还要求逐区对照原图和译图；无法辨认的区域保留疑点。数字检查对比数值集合，可以发现数量改变，却未必发现两个位置的数值互换。模型自查也可能重复第一次的误判，不能据此声称比单次翻译提高某个固定百分比。

**公开范围。** 仓库提供核心代码节选、合成样张与静态演示，不包含真实图纸、模型密钥、生产账号或后台服务。可在仓库根目录运行 `python -m http.server --directory docs 8000`，然后用浏览器访问本机 8000 端口。回归检查：`node --test projects/engineering-translation/checks.test.mjs`。
