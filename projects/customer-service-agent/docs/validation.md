# 验证与实现边界

_记录公开节选的复现方法，区分完整项目历史验证与本仓库验证。_

## 本仓库检查

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python demo.py
```

在仓库根目录运行 `python scripts/check_public_content.py` 检查常见敏感文件与生产信息，或运行 `python scripts/run_checks.py` 一次完成公开检查、测试与演示。当前凭证没有工作流上传权限，仓库未启用 GitHub Actions。

## 覆盖范围

- 预约确认、改期和付款证据规则的领域状态机。
- 重复消息、重试、持久化任务、重启恢复与人工期间静默。
- 企业微信回调验签、AES 解密、错误接收方和重复回调。
- 人工交还 AI 时的平台状态查询、失败处理和旧任务保护。
- 员工签名链接、会话签名、过期拒绝与 CSRF 工具。
- 虚构 Markdown 知识的分块、加权检索和无命中行为。

测试全部使用临时数据库和合成资料，传输层被替换为本地伪实现。

2026-11-05，公开节选在本地运行 61 项测试全部通过，离线演示完成。后续提交以实际运行输出为准。

## 完整项目与公开节选

完整项目在最近一次功能修复后的本地回归为 162 项通过；这是完整项目的历史记录，不是本仓库测试数量。本仓库只包含经脱敏的部分模块与测试，运行输出反映其自身数量。

完整项目接入过真实企业微信普通咨询；公开 `demo.py` 为离线确定性演示，不能作为线上回复耗时、模型质量或业务转化效果证据。近期人工交还 AI 修复也不能仅凭本地测试视为新一轮真实会话端到端验收完成。

## 尚未具备或尚未验证

- Embedding、向量数据库和图片向量检索未在当前系统实现。
- OCR 只能辅助识别截图，未接入支付平台到账核验。
- 没有可公开复现的高并发压测、准确率、成本节省或转化率结论。
- 没有宣称消息传输严格 exactly-once，或彻底消除模型幻觉。
- 公开节选不是开箱即用的完整生产服务，不包含所有安全、业务和运维模块。
