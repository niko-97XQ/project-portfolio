# 工程案例与面试讨论

## Contact 不应改变整个页面的观感

**现象**：预约表单常驻页面，打断了影像浏览；直接使用锚点跳转，也不等于用户主动要填写表单。

**处理**：把表单放进默认关闭的原生 dialog，只由 Contact 或 Appointment 的显式点击打开。URL 含 `#contact` 或 `#appointmentForm` 本身不会打开弹窗。关闭时保留未提交草稿，恢复页面滚动；后台提交完成时不把已经关闭的窗口重新弹出。

**回归重点**：初始关闭、显式打开、Escape、按钮和遮罩关闭、焦点返回、关闭后页面可滚动，以及跨页面返回时不意外唤起表单。

## 超时不等于提交失败

**风险**：服务器已写入，响应却未到达浏览器。若重试重新生成请求键，就会新增一条相同申请；只在按钮上加 disabled 也无法处理刷新、重启或并发请求。

**处理**：表单内容未变时复用 UUID，后端保存键与规范化内容摘要，在同一事务中完成重复检查和写入。同键同内容返回原编号，同键不同内容拒绝为冲突。

**可复现证据**：`test_retry_returns_same_reference`、`test_retry_survives_store_recreation`、`test_changed_payload_conflicts` 和六个并发请求的回归。它证明的是申请接收的幂等行为，不是所有下游操作严格 exactly-once。

## 横向浏览如何保持单一滚动逻辑

**取舍**：款式横向排列，但鼠标滚轮继续控制页面的垂直滚动。额外的横向进度条会产生第二套交互和移动端尺寸问题。

**处理**：横向位移由章节进度驱动，左右键转换为同一进度上的页面位置。尺寸改变后重新测量卡片和图注，不把桌面的固定尺寸直接套到手机。降低动态效果时直接展示网格。

**讨论点**：长章节会增加浏览距离；图片内容和文案长度变化也会影响舞台高度。滚动体验需要实际视口检查，不能仅凭 transform 数值证明布局正确。

## 实时试纱：接入准备不等于产品可用

项目探索过第三方实时试穿，已实现本地摄像头预览和资源清理，但未完成稳定的真实模型接入。外部演示加载问题的诊断与一次隔离测试恢复，不能当作端到端试穿已经验收。

本仓库将该模块明确标为准备页，不借用普通视频画面冒充 AI 换装，也不宣称能准确还原所有婚纱。外部服务授权、费用、网络、隐私同意及复杂款式效果，都需要单独验收。
