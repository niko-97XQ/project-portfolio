# 架构与数据流

## 展示层

`web/index.html` 保留展示页的章节结构；布局脚本、滚动增强与预约提交分开管理。公开版移除远程字体、真实照片和品牌 Logo，使用系统字体及原型内置矢量示意图，页面初始加载不依赖第三方服务。

滚动横移并非再嵌套一条横向滚动条：测量 `track.scrollWidth - viewport.clientWidth` 得到横向距离，再由章节的垂直滚动进度计算 `translate3d`。窗口尺寸、字体就绪和容器尺寸变化会触发重新测量。键盘左右键操作同一条垂直时间轴。

`prefers-reduced-motion` 下取消固定滚动舞台与画面变换，以可直接阅读的网格呈现内容。保留这一分支，比单纯把动画时长改成零更重要。

## 预约申请链路

```text
浏览器填写虚构资料
  -> URL-encoded POST /website/appointments
  -> 本机 HTTP 适配器：路由、类型、大小、重复字段限制
  -> 输入策略：Origin、同意声明、日期、联系方式、UUID
  -> SQLite BEGIN IMMEDIATE
       -> 相同键与相同摘要：返回已有编号
       -> 相同键与不同摘要：拒绝冲突
       -> 校验客户端及联系方式的频率限制
       -> 写入待联系申请与限流事件
  -> 201 新建 / 200 安全重试，返回不透明编号与 pending
```

前端为每组表单内容保留一个 UUID。网络超时后，提交可能已经在服务端完成，所以提示重试但不立即生成新键。后端不依赖前端的 busy 状态：唯一约束和事务确保并发重试不会插入多份记录。

客户端标识以数据库内随机密钥生成 HMAC 摘要，不直接写入限流表。联系方式用于后续联系及号码限流，因此仍属于需保护的数据；公开演示只使用合成号码，结束后删除临时数据库。这不意味着可以把生产联系方式放进公开仓库。

## 员工处理与边界

申请状态只有 `new`、`contacted` 和 `closed`。存储层以 `WHERE id=? AND version=?` 防止两个操作员覆盖彼此修改，并记录处理事件。状态不是正式预约状态，不能代替库存、档期或付款核验。

公开 HTTP 适配器没有员工处理路由或申请列表。`update_status()` 是内部存储接口，必须由具备认证、权限、CSRF 和业务校验的外围服务调用；不能把它直接映射成匿名 HTTP 写接口。

## 摄像头准备页

开启操作才请求 `getUserMedia`，仅请求视频。页面关闭、进入后台、设备断开或启动失败时释放轨道；授权请求完成得太晚时，用版本号识别过期结果并立即停止。此模块未连接实时模型，显示的是原始画面，不能当成换装效果。

## 可部署性与非目标

完整项目采用静态资源与业务后端分离的方式，已做过发布和回滚准备。本仓库不包含生产网关、服务器连接信息、私有媒体或环境配置。本机适配器只用于复现核心交互，不承担公网 HTTPS、员工认证、全局防刷、审计合规或生产运维职责。
