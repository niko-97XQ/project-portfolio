# 婚纱工作室网站：滚动交互与预约申请

面向婚纱工作室的展示与预约入口。这里公开经脱敏的前端源码、预约接收策略、SQLite 存储模块及本机演示，不是生产站点备份。

**可以复现的主流程：浏览款式 → 点击 Contact → 填写虚构资料 → HTTP 提交 → SQLite 落库 → 返回待确认编号。**

## 项目背景

工作室需要兼顾影像展示与预约转化：页面保留轻量的编辑式布局，通过滚动浏览款式，但不能让预约表单一直占据展示区域。预约申请还需要可靠送达，避免重试产生重复记录，并交由员工确认，而不是自动锁定档期。

完整项目曾进行服务器部署和员工后台联调。本仓库不提供生产地址、员工权限、真实品牌清单、客户资料或商品照片。公开界面的品牌、地址和款式均为演示替换项；图片位置使用原型内置的矢量示意图，不代表真实服装上身效果。

## 快速运行

Python 3.12+，基础演示和后端测试只使用标准库，不需要密钥、账号或生产数据库。

```bash
cd projects/bridal-studio-website
python demo.py
python -m unittest discover -s tests -v
python demo.py --serve
```

前两条运行命令会结束，最后一条启动仅监听本机的服务，并输出实际浏览器地址。打开该地址查看完整交互；按 Ctrl+C 结束服务。数据库位于临时目录，结束后清理，**请勿填写真实客户资料**。

可选的浏览器回归：

```bash
npm install
npx playwright install chromium
npm run verify:ui
```

浏览器脚本会自动启动临时本机服务，使用模拟视频流，不打开真实摄像头、不上传媒体。截图写入忽略提交的 `artifacts/`，不会公开真实影像。

## 阅读代码

- [滚动时间轴](web/assets/v13-editorial.js)：测量横向距离，把垂直滚动归一化为位移；通过 `requestAnimationFrame` 合并更新。
- [弹窗和提交状态](web/assets/v13-contact.js)：显式打开、焦点管理、超时反馈，以及内容未变时沿用同一个提交键。
- [预约输入策略](src/bridal_demo/intake.py)：同源、同意声明、日期、联系方式与 UUID 校验。
- [事务存储](src/bridal_demo/store.py)：在同一个事务中处理去重、冲突检测、限流和插入；员工更新使用行版本检查。
- [隔离 HTTP 适配器](src/bridal_demo/http_demo.py)：连接前端与真实存储，限制请求大小，不暴露申请列表或运行目录。
- [摄像头生命周期](web/assets/v13-tryon.js)：处理授权迟到、设备结束、页面隐藏和离开页面时的清理。

## 设计取舍

1. 展示页使用原生 HTML、CSS 与 JavaScript，没有为了滚动动效引入整个应用框架。
2. 动效作为增强层：减少动态效果时取消固定滚动时间轴，仍能正常阅读内容。
3. 申请与确认分开：提交成功只表示收到意向，不等于预约已确认、已收款或库存可用。
4. 前端不能独自保证去重：由持久化存储结合唯一键和事务兜底，重启后仍能识别同一请求。
5. 公开演示不复制员工身份体系：认证、CSRF 与运营流程属于外围服务；此处只公开可独立审查的预约策略和存储边界。
